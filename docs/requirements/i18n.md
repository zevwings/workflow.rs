# 国际化 (i18n) 支持实施方案

## 📋 项目概述

**目标**: 为 Workflow CLI 引入完整的国际化（i18n）支持，使工具能够服务全球用户，提升用户体验。

**状态**: ⏳ 待实施
**实现度**: 0%
**时间估算**: 10-15 天
**优先级**: 高

---

## 🎯 需求分析

### 一、现状

Workflow CLI 目前存在多语言混用的情况：

#### 1.1 CLI 界面文本
- **中文为主**: CLI 命令描述、参数说明大量使用中文
  ```rust
  /// 显示版本信息
  Version,
  /// 交互式初始化或更新配置
  Setup,
  ```

#### 1.2 日志消息
- **中英文混合**: 日志输出既有中文也有英文
  ```rust
  info!("开始三阶段提交分析（当前分支相对基准分支）...");
  info!("Installing binaries to {}...", install_dir.display());
  ```

#### 1.3 错误和提示消息
- **中英文混合**: 用户可见的错误提示、交互提示混用两种语言
  ```rust
  "Failed to get default branch: {}"
  "Branch '{}' already exists"
  "Create from current branch ({})"
  ```

#### 1.4 LLM 提示词模板
- **纯英文**: 所有 LLM prompt 都是英文
  - `crates/services/src/summary/prompt/*.md` (6 个文件)
  - 包含详细的分析任务说明和 JSON schema

### 二、问题与挑战

#### 2.1 用户体验问题
- 非中文用户难以使用（CLI 帮助文本、错误提示为中文）
- 非英文用户难以理解 LLM 输出结果
- 语言不一致降低专业性

#### 2.2 维护问题
- 硬编码文本散落在代码各处
- 修改文本需要改动代码
- 难以保证翻译质量和一致性

#### 2.3 技术挑战
- **Rust i18n 生态选型**: 需要选择合适的 i18n 库
- **编译时 vs 运行时**: 性能与灵活性的权衡
- **LLM Prompt 多语言**: 不同语言对 LLM 效果的影响
- **模板引擎集成**: 现有模板系统（`crates/toolkit/src/template/engine.rs`）的兼容性

### 三、目标

#### 3.1 功能目标
- ✅ 支持中英文双语（可扩展更多语言）
- ✅ 自动检测系统语言或通过配置指定
- ✅ 所有用户可见文本支持多语言
- ✅ 提供语言切换机制

#### 3.2 质量目标
- ✅ 零性能损耗（编译时处理）
- ✅ 类型安全（编译期检查翻译键）
- ✅ 易于维护（集中管理翻译文件）
- ✅ 易于扩展（添加新语言简单）

## 🔧 技术方案

### 一、技术选型

#### 1.1 i18n 框架选择

**推荐方案**: [rust-i18n](https://github.com/longbridgetech/rust-i18n)

**理由**:
1. **编译时处理**: 零运行时开销
2. **类型安全**: 编译期检查翻译键
3. **宏支持**: 类似 `format!` 的使用体验
4. **YAML 格式**: 易读易写的翻译文件
5. **活跃维护**: 社区活跃，文档完善

**备选方案**:
- `fluent-rs`: Mozilla 的方案，功能强大但复杂度高
- `gettext-rs`: 传统方案，工具链成熟但 Rust 生态集成度低

#### 1.2 语言检测策略

```rust
// 优先级：CLI 参数 > 环境变量 > 配置文件 > 系统语言 > 英文（默认）
fn detect_language() -> Language {
    if let Some(lang) = get_cli_language() {
        return lang;
    }

    if let Some(lang) = env::var("WORKFLOW_LANG").ok() {
        return Language::from_str(&lang).unwrap_or_default();
    }

    if let Some(lang) = load_config_language() {
        return lang;
    }

    if let Some(lang) = detect_system_language() {
        return lang;
    }

    Language::English
}
```

#### 2.3 使用方式

```rust
// 1. 简单文本
use crate::i18n::t;

println!("{}", t!("cli.commands.version"));
// 输出: "Show version information" (en) 或 "显示版本信息" (zh-CN)

// 2. 带参数的文本
println!("{}", t!("errors.branch.already_exists", branch = "main"));
// 输出: "Branch 'main' already exists" (en) 或 "分支 'main' 已存在" (zh-CN)

// 3. CLI 属性宏中使用
#[derive(Subcommand)]
pub enum Command {
    /// %t(cli.commands.version)
    Version,
    /// %t(cli.commands.check)
    Check,
}
```

### 三、LLM Prompt 多语言方案

#### 3.1 方案选择

**推荐**: **保持英文 Prompt + 本地化输出说明**

**理由**:
1. 大多数主流 LLM 对英文理解最好
2. 英文 Prompt 能获得更稳定的输出质量
3. 减少翻译维护成本

**实施方式**:
```markdown
<!-- crates/services/src/summary/prompt/classify_files.md -->
You are a code commit analysis expert. Please analyze the file change list provided by the user and perform intelligent classification.

## Output Language

**IMPORTANT**: Please output your analysis in **%{output_language}** language.
- If output_language is "Chinese", use Chinese (简体中文) for all text content
- If output_language is "English", use English for all text content
- Field names in JSON must remain in English (e.g., "batch_summary", "common_changes")

## Analysis Tasks
...
```

#### 3.2 备选方案（低优先级）

为每种语言维护独立的 Prompt 模板：
```
crates/services/src/summary/prompt/
├── en/
│   ├── classify_files.md
│   ├── analyze_batch.md
│   └── ...
└── zh-CN/
    ├── classify_files.md
    ├── analyze_batch.md
    └── ...
```

### 四、配置管理

#### 4.1 全局配置扩展

**位置**: `~/.workflow/config/workflow.toml`

```toml
[general]
# 语言设置（留空则自动检测）
language = "zh-CN"  # 可选值: "en", "zh-CN"

# LLM 输出语言（留空则跟随 language）
llm_output_language = "zh-CN"
```

#### 4.2 环境变量支持

```bash
# 设置语言
export WORKFLOW_LANG=en

# 单次命令指定语言
workflow --lang=en branch create
```

## 📝 注意事项

### 开发注意事项

1. **翻译键命名规范**
   - 使用小写字母和下划线
   - 采用层级结构（如 `cli.commands.version`）
   - 避免过长的键名

2. **参数插值规范**
   - 使用 `%{param}` 格式
   - 参数名使用 snake_case
   - 必要时提供类型转换

3. **翻译文本规范**
   - 保持简洁明了
   - 避免文化特定的表达
   - 注意标点符号差异

4. **LLM Prompt 注意**
   - 优先使用英文 Prompt
   - 只在输出说明中指定语言
   - 验证不同语言的输出质量

### 测试注意事项

1. **边界情况**
   - 翻译键不存在
   - 参数缺失
   - 语言代码无效

2. **性能测试**
   - 验证编译时处理无运行时开销
   - 测试大量文本的处理性能

3. **兼容性测试**
   - 不同平台的语言检测
   - 不同 shell 的环境变量
   - 不同版本的配置文件
