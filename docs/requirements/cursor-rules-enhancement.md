### 目标

通过对比分析参考项目（workflow.py）的 `.cursor/rules/` 目录，发现当前项目的规则文件缺少关键的执行机制和详细规范。本需求旨在：

- `README.mdc` - 规则文件说明

参考项目（workflow.py）的规则文件结构相同，但内容更加详细和完善，特别是包含了：

#### 2.1 快速决策树（优先级：高）

**位置**: 在"核心原则"之后、"代码生成规范"之前

**需要添加的内容**:

1. **白名单检查流程**
   - 检查用户消息是否包含"生成代码"、"创建代码"、"写代码"、"实现"、"修改代码"、"更新代码"、"添加功能"、"修复bug"、"优化代码"等关键词

2. **黑名单检查流程**
   - 检查用户消息是否包含"分析"、"总结"、"检查"、"诊断"、"排查"、"查看"、"讨论"、"审查"、"review"等关键词
   - 如果包含 → 立即停止，改为聊天文本响应（这些词是黑名单，禁止生成/修改代码）
   - 如果不包含 → 继续下一步

3. **二次确认流程**
   - 询问用户："准备生成/修改以下代码：[文件路径或新文件说明]，修改内容：[简要说明]，确认要生成/修改吗？"
   - 用户明确确认（回复"是"、"确认"、"可以"等） → 继续下一步
   - 用户未确认或拒绝 → 立即停止，改为聊天文本响应

4. **关键警告说明**
   - 强调"分析"、"总结"、"检查"、"讨论"、"审查"等词是黑名单关键词
   - 说明任何 STOP 都必须立即停止，不能继续执行后续步骤
   - 说明不能跳过任何检查，必须按顺序执行
   - 说明不能"先生成再解释"，必须在生成前通过所有检查

**格式要求**:
- 使用清晰的步骤编号（1、2、3、4）
- 使用 ✅/❌ 标记表示通过/失败
- 使用 ❓ 标记表示检查点
