# Workflow 架构设计

## 📋 项目概述

Workflow 是一个 Rust 编写的 CLI 工具，用于自动化开发工作流，提供 PR 管理、Jira 集成、日志处理等功能。v2 采用 Cargo workspace 多 crate 结构。

---

## 🏛️ 架构层次

### Workspace 与 Crate 结构（v2）

```
┌─────────────────────────────────────────────────────────┐
│  crates/app（CLI 入口）                                   │
│  - bin/workflow.rs（主命令）                              │
│  - bin/install.rs（安装命令）                             │
│  - cli/（参数与子命令定义）                               │
│  - commands/（命令实现）                                  │
│  - workflows/（工作流编排与展示）                         │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  crates/domain（领域模型与接口）                          │
│  - config/（全局与仓库配置、校验）                         │
│  - git/（Git 实体与仓库抽象）                             │
│  - jira/、github/、llm/、pr/、cnb/（各领域实体与仓储）   │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  crates/storage（存储与 Git 实现）                        │
│  - git/（Git 操作、分支/提交/标签/远程等）                │
│  - cnb/（CNB 平台客户端）                                 │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  crates/services（应用服务）                              │
│  - pull_request/（PR 服务）                               │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  crates/toolkit（通用能力）                               │
│  - http/（HTTP 客户端、重试）                             │
│  - logger/、paths/、template/、util/（日志、路径、模板等） │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  crates/prompt（交互与输出）                              │
│  - dialog/、form/、output/、style/（对话框、表单、进度等） │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  crates/registry（依赖注入）                              │
│  - 容器与绑定，供 app 解析服务                            │
└─────────────────────────────────────────────────────────┘
```

### 模块职责

- **app**：CLI 入口与命令分发；解析参数后委托给各 `commands` 与 `workflows`。
- **domain**：领域实体、配置模型与仓储 trait，不依赖具体实现。
- **storage**：Git 与 CNB 等存储/平台实现，实现 domain 中的仓储。
- **services**：跨领域应用服务（如 PR 流程）。
- **toolkit**：HTTP、日志、路径、模板、文件等通用工具。
- **prompt**：交互式对话框、表单、进度条与输出样式。
- **registry**：依赖注入，将 domain/storage/services 等绑定到 app。

### 数据流向

```
用户输入 → app (Cli) → commands/* → domain / storage / services → 执行操作
```

## 🧠 开发与构建

- **构建主二进制**：`cargo build -p app` 或 `cargo build --release -p app`
- **运行**：`cargo run -p app`（默认 `workflow` bin）或 `cargo run -p app --bin install`
- **测试**：`cargo test`（workspace 下会运行各 crate 的测试）
- **文档**：`cargo doc --open`（可指定 `-p app` 等）

---

## 💾 数据存储

### 配置文件位置

- `~/.workflow/` 下全局配置（具体路径由 `toolkit::paths` 等定义）
- `.workflow/config.toml` - 项目级配置（分支、仓库等）

配置结构与 v1 兼容，详见各 crate 的 config 模块。
